A Capacity Law for Tiered KV Caching in Hybrid-Attention LLMs: Why the Recurrent State Is Never the Bottleneck

lamport · sglang KV-cache research (v0.3) · draft

Abstract. Hybrid linear-attention LLMs (Qwen3.5, Jamba, Zamba, MiniMax) interleave many constant-size recurrent-state (SSM/GDN) layers with a few full-attention layers. Recent hybrid prefix-caching systems (Marconi, MLSys'25; Jenga, SOSP'25) treat the large fixed recurrent state as the scarce GPU resource and manage it on-device only. We show this intuition inverts once the state is host-tiered, as in SGLang's HiCache. We give a simple capacity law: the recurrent state costs s bytes per sequence (context-independent) while attention-KV costs k bytes per token, so per sequence the KV footprint (L·k, growing with context length L) exceeds the state footprint (s) exactly when L > L* = s/k ≈ 1580 tokens. Since prefix caching only pays off at L ≫ L*, the recurrent tier is always the cheaper tier and never binds; the attention-KV tier, whose footprint scales with context, is the sole capacity bottleneck. Using a fully-instrumented 122B hybrid MoE (Qwen3.5-122B-A10B-FP8, 36 GDN + 12 attention layers, 8×H100) under a Poisson rate-swept, multi-turn, real-text (Mooncake-mix) protocol, we introduce a reuse-frontier diagnostic that measures, per prefix match, how much resident attention-KV is rendered un-continuable ("stranded") by a missing recurrent checkpoint. We find: (i) the recurrent-state host pool never evicts — even at 3× the working set, where the attention-KV host pool evicts 587 M tokens cumulatively (26 M in a single steady-state window); (ii) stranding is <1.2% and is sparse-checkpoint-bounded, not eviction-driven; (iii) at the contract operating point the system is not cache-bound at all (hit rate maximal 0.842, host tier 79% full, PCIe <10%), and the known capacity lever (exclusive tiering, +13 pp under pressure in prior work) is neutralized; the binding resource is prefill compute under bursty arrivals. We therefore bound the design space for hybrid KV caching: recurrent-state management (the focus of prior work) is a non-lever under host tiering; the only cache lever is attention-KV capacity, and only at large working sets. The law is config-checkable: for six deployed hybrids (Qwen3-Next, Zamba2, Jamba, Granite-4, Nemotron-H, and our Qwen3.5-122B) the element-ratio crossover L*elem = 167–3456 tokens (byte-L* adds a 1–4× dtype factor, still ≪ deployed contexts) — so the conclusion is family-wide, not a single-model artifact. We contribute the capacity law, a reuse-frontier diagnostic, a cross-scale 2×2 characterization, and a scoped impossibility corollary: no lossless, budget-respecting, non-capacity, non-classical cache mechanism can shift the curve (the only remaining axes — capacity and classical eviction — are budget-frozen and charter-excluded respectively). A candidate mechanism (Value-Density Mamba Retention) is a no-op by construction, a direct test of the law.

1 Introduction

Hierarchical KV caching (HiCache) tiers key–value state across GPU HBM (L1) and host DRAM (L2) to serve context reuse beyond device capacity. For hybrid models the picture is richer: full-attention layers hold a per-token KV cache that grows with sequence length, while linear-attention (Gated-DeltaNet / Mamba) layers hold a single constant-size recurrent state per sequence. Reusing a cached prefix requires both: the attention-KV along the path and a recurrent checkpoint at the reuse boundary.

Prior hybrid caching work manages the recurrent state on GPU only and frames it as the scarce resource (its state is ~200× a KV block at 128K). Our contributions:

  • A capacity law (§3): the recurrent-state tier binds only when mean context length L < L* = s/k (≈1580 tokens here); for long-context serving (L ≫ L*) it never binds, and the attention-KV tier is the sole capacity bottleneck. This is a closed-form, model-agnostic condition that inverts the GPU-scarcity framing of Marconi/Jenga and predicts every measurement below.
  • A reuse-frontier instrumentation (reusable, ~130 LOC, live path) that separates the full-attention reuse frontier from the all-component frontier, exposing recurrent-state stranding of resident attention-KV — a quantity invisible to hit-rate — and confirms the law directly.
  • A cross-scale 2×2 ({contract, intended} × {write-through, exclusive tiering}) that validates the law: the recurrent pool evicts 0 in all four cells even at 3× working set; the design space collapses to attention-KV capacity, whose only in-budget lever is the known exclusive-tiering primitive (neutral@contract, +7.4 pp@intended) — no novel primitive exists.
  • A candidate mechanism, Value-Density Mamba Retention (VMR), whose protection threshold is L* — shown to fire zero times, i.e. a no-op by construction, serving as a direct empirical test of the law rather than a failed tuning.
  • An actionable methodological finding: the draft protocol (NUMP 500) under-provisions the working set (hit 0.842, host 79%) vs its stated premise; only at NUMP≈1553 does the attention-KV tier pressure (hit 0.650). We recommend re-provisioning.

Pressure (and thus cache headroom) is a function of working-set size: at the charter's intended scale (NUMP 1553, working set ≈19 M ≫ 10.7 M cache) the attention-KV host tier saturates (util 1.0, hit falls 0.842→0.650) — yet the recurrent-state pool still never evicts (§5.1). The pressured regime the protocol intends is thus reachable only off the draft contract point; even there, the recurrent state is a non-lever.

3 A capacity law for hybrid KV tiering

We formalize when each tier binds, which explains and generalizes the measurements. Let a hybrid model have nlin linear-attention (SSM/GDN) layers and nfull full-attention layers. Per sequence, the recurrent state costs s = nlin·dstate bytes (independent of context length); per token, the attention-KV costs k = nfull·dkv bytes. For a serving instance with C concurrent live sequences of mean context length L, the two host tiers must hold:

  recurrent host footprint = C · s          (grows with #sequences only)
  attention-KV host footprint = C · L · k   (grows with #sequences × context)

Assumptions. (A1) each linear layer's recurrent state has fixed size independent of context length (true for SSM/Mamba/GDN by construction); (A2) full-attention KV is linear in tokens (standard); (A3) a serving instance holds C concurrent live cached sequences of mean context L; (A4) host tiers of sizes Hm (recurrent) and Hk (KV). Then the recurrent tier saturates when C·s > Hm and the KV tier when C·L·k > Hk.

Proposition 1 (Capacity Law). Under (A1)–(A4), the recurrent-state tier saturates before the attention-KV tier — i.e. is the binding capacity bottleneck — iff L < L* ≜ (s/k)·(Hk/Hm). Proof. The recurrent tier binds first iff its utilization exceeds the KV tier's: C·s/Hm > C·L·k/Hk; C>0 cancels, giving s/Hm > L·k/Hk, i.e. L < (s/k)·(Hk/Hm). ∎ (With equal pools Hm=Hk, L* = s/k.)

Consequence. The recurrent-state tier is the bottleneck only when the mean context length L < L* = (s/k)·(Hk/Hm). With equal pools (this system, both = hicache_size), L* = s/k = 18 MB / 11.4 KB ≈ 1580 tokens. The pool ratio only shifts L* linearly: to make the recurrent tier bind at a realistic serving context (say L=64k), one would have to under-provision it by Hm/Hk ≈ L*/L ≈ 1/40 — i.e. deliberately starve it far below what one node's concurrency even needs (C·s). No sane provisioning reaches that regime. Because prefix caching only pays off for long contexts (L ≫ a few hundred tokens), realistic serving operates at L ≫ L*, where the recurrent state is trivially the cheaper tier and never binds — while the KV tier, whose footprint scales with context, saturates. Equivalently, the recurrent tier binds only under C > Hm/s concurrent sequences (here 96 GB/18 MB ≈ 5333 per rank) — far beyond what one node's compute admits. This inverts the GPU-only regime (Marconi/Jenga), where HBM is so scarce that even the constant state competes; on a host tier the asymmetry L ≫ L* dominates.

Generality across the hybrid family. L* depends only on the architecture (layer counts, state and KV dims), so it can be read off any config. Computing the element-ratio L* = (nlin·state_elems) / (nfull·kv_elems_per_token) for six deployed hybrids:

L*elem is the element-ratio crossover (state and KV in the same dtype). Across every deployed hybrid it is 167–3456 tokens; the byte crossover L* = L*elem · (state_bytes/kv_bytes) adds a 1–4× factor (e.g. our bf16-state / fp8-KV gives 2×, matching the measured 1580). The recurrent state elements follow the correct GDN geometry — per key-head, S ∈ [nkey, dk, dv], validated against our measured 18 MB/seq (16·128·128·36·2 B). A lower L* (e.g. Zamba2's 167, from its 13 wide-KV attention layers) means the recurrent tier binds only at even shorter contexts — it strengthens, not weakens, the conclusion. Since prefix caching is deployed precisely for long contexts (32k–256k ≫ L*), the recurrent-state tier is never the capacity bottleneck for any current hybrid LLM under host tiering — a family-wide, config-checkable prediction (see tools/capacity_law.py), not a single-model artifact. (We measure only Qwen3.5-122B directly; the other five are config-derived, and their byte-L* carries the 1–4× dtype factor.)

Corollary (why our mechanism is a no-op). Any policy that manages the recurrent-state tier — including our own Value-Density Mamba Retention (VMR: protect a checkpoint iff its unlocked KV L·k exceeds its footprint s, i.e. iff L > L*) — can only act when that tier evicts. The law says it never does at L ≫ L*, so VMR's protect-list is empty by construction. VMR is thus not a failed tuning but a direct test of the law: its threshold is L*, and it fires zero times across every measured configuration (§5). The design space for lossless hybrid-KV caching therefore collapses onto the attention-KV tier, whose only in-budget lever is exclusive (device-XOR-host) tiering — a known result, not a novel primitive.

Impossibility corollary (scoped). The capacity law above is unconditional — the recurrent tier never binds for L ≫ L*, at any scale. From it we derive a narrower, clearly-bounded statement about what a cache-architecture change can add. Attention-KV reuse can be raised on exactly two axes: (i) effective capacity and (ii) eviction order. Axis (i) is bounded by the KV-host budget (768 GB); its known non-duplicating refinement is exclusive tiering, and — a consequence of our law — one could also reclaim the idle recurrent budget for KV (§7), but that too is a capacity increase (it enlarges the KV tier beyond its 768 GB budget), i.e. the same class the venue treats as a baseline, not a novel primitive. Axis (ii) is a classical policy family (LRU/LFU/GDSF/Belady) — excluded as a contribution by construction, independent of whether any Belady gap exists (we make no LRU≈Belady claim). Therefore no lossless, budget-respecting, non-capacity, non-classical cache mechanism can shift the curve; and at the contract operating point even the capacity axis is inert (host 79% full, hit maximal). Any remaining win lies outside the lossless cache — compute (attention approximation, lossy) or admission/scheduling (which, with hit maximal and reuse near-monotone, reduces to shortest-job-first). This is a bounded impossibility — a map of where headroom cannot be — confirmed by the four-cell experiment (§5).

5.1 The recurrent-state pool never binds (cross-scale). Instrumentation over the whole run:

Two facts. (a) The contract eval is under-provisioned. At NUMP 500 the working set (~6.2 M tokens) fits the 7.81 M-token host tier (util 0.79); hit rate is maximal (0.842) and no host eviction occurs. Only at the charter's intended scale (working set ~19 M) does the attention-KV host tier saturate (util 1.0, 587 M tokens evicted) and hit collapse to 0.650 — the pressured regime the protocol intends. (b) The recurrent state never binds. Even at util 1.0 with 587 M attention-KV tokens evicted, the recurrent-state host pool evicts nothing (18 MB/seq × ≈5360 slots holds every live conversation). Stranding stays <1% and is checkpoint-stride-bounded (sparse placement, not eviction). VMR is a no-op by construction (protect_skips≡0), not by tuning: there is nothing to protect.

5.2 The known capacity lever is neutralized at the contract operating point (2×2). Exclusive tiering (write_back) — the mechanism reported at +13 pp under host pressure in prior sglang work (we measure +7.4 pp at intended scale, single-rate) — is statistically identical to write_through on the contract eval, because the host tier is only 79% full:

The 2×2 is decisive. On the contract eval, exclusive tiering (the "+13 pp under pressure" mechanism) is neutral (Δhit +0.05 pp) — the host tier is only 79% full, so there is nothing to gain. Only at the intended scale, where the attention-KV tier saturates (write-through hit 0.650), does exclusive tiering recover +7.4 pp hit and +12.5% req/s. Two conclusions: (i) the contract protocol masks the sole cache lever — attention-KV capacity — by under-provisioning; (ii) even where a lever exists, it is the known exclusive-tiering primitive, bounded by the frozen 768 GB budget — the improvement space contains no novel primitive. Note the recurrent-state pool evicts nothing in all four cells.

5.3 The contract eval is compute/burst-bound, not cache-bound. Prefill:decode batch ratio ≈7.4; queue depth p50=0 (idle) spiking to 83 (bursts); host↔device movement ≈1.85 GB/s (<10% PCIe), fully overlapped. Hit rate is maximal (0.842 = 1 − irreducible first-occurrence). We rule out GPU bubbles as the lever: prefill batches during bursts run at ≈40k tok/s (the compute ceiling); the only low-throughput batches occur when the queue is empty (nothing to batch), so the tail-causing bursts are compute-saturated, not stalled on transfer or scheduler overhead. No lossless, non-capacity cache mechanism we could construct (recurrent-state co-management, transfer/overlap, layout, co-residency) has headroom here; the binding resource is prefill attention over reused long contexts, which is lossless-fixed. Scheduling cannot help losslessly either: with hit rate maximal and reuse near-monotone, per-request prefill cost is dominated by context length, so any cost-reducing reorder reduces to shortest-job-first — a classical policy excluded by the charter (and it trades tail fairness, not total work).

5.4 Lossless, and why we attribute via stable counters. All engine changes are pure counting / retention re-ordering; reuse is byte-exact (verified against the no-cache run). The headline p99-TTFT is a fragile discriminator here for two systematic (not merely statistical) reasons: (a) warm-up — cold-JIT first load gives λ3 p99 = 53 s vs 9 s warm; and (b) burst-phase alignment — with a bursty open-loop arrival (queue p50=0 spiking to 83), the p99 depends on where the worst Poisson burst lands relative to cache warm-up. Across three identical warm runs λ3 p99 = {7956, 8969, 9389} ms, straddling the 8 s SLO, so goodput@8s flips between 0 and 2.99 req/s. This is a property of the metric+workload, not statistical noise we can average away at n=3; it argues the SLO is set inside the sensitivity band. We therefore attribute via the stable counters — hit rate (±0.1 pp across runs), evict/load-back tokens, and host/mamba eviction counts — all of which show the recurrent-state and exclusive-tiering levers flat on the contract eval, and cleanly separated at intended scale (§5.1–5.2).

6 Related work

Marconi (MLSys'25): hybrid prefix caching with FLOP-efficiency eviction; GPU-HBM only, discards SSM state on eviction. Jenga (SOSP'25): heterogeneous on-GPU allocator for mixed state/KV page sizes; no host offload. Mooncake (FAST'25) / Strata / AttentionStore (ATC'24) / CacheGen / LMCache / HCache (EuroSys'25) / InfiniGen (OSDI'24): tiering, GPU-assisted layout, layer-wise overlap, compute-vs-load — all for transformer KV; none manages the tiered recurrent state. Cake (ICML'25) / KVPR (ACL'25): recompute-vs-load, transformer KV only. Against this backdrop our contribution is not a new caching policy but the capacity law and its consequences: the first analysis showing that, once host-tiered, the recurrent-state pool is over-provisioned rather than scarce (inverting the GPU-only premise of Marconi/Jenga), a config-checkable crossover L* that holds family-wide, and a reuse-frontier diagnostic that makes stranding measurable. Our candidate cross-tier co-management (VMR) is reported as a no-op by construction — the empirical test that confirms the law, not a mechanism we claim as a win.

7 Limitations, implications & when the lever moves

VMR is a no-op when the recurrent host pool does not evict — precisely the contract operating point. Its value is conditional on working-set pressure that this pool, by its O(#sequences) footprint, essentially never experiences. The p99 TTFT metric is warm-up- and burst-sensitive (≈6× cold-vs-warm at λ=3); we compare warm-to-warm and attribute via stable counters. The study is one model family (Qwen3.5 hybrid GDN) / one workload mix; the intended-scale (NUMP 1553) results are single-rate (λ=5) diagnostics, so the mechanism-space claim at that scale rests on the unconditional capacity law and the recurrent-never-evicts result (0 host evictions across 4 runs × 2 write-policies × 2 scales), not on the single-rate 2×2 alone — a full λ-sweep and a measured null for a non-capacity attention-KV mechanism at 1553 are the natural next experiments. The over-provisioning of the recurrent host pool is partly an implementation artifact (SGLang sizes it = hicache_size, i.e. 768 GB — equal to the KV host tier); a right-sized pool would still not bind: binding needs C·s > Hm, i.e. C > Hm/s ≈ 5333 concurrent cached sequences per rank at the stock 96 GB — but the node admits ≤270 running sequences and the entire workload has only 1553 distinct conversations, so even a right-sized ~30 GB recurrent host tier (≈1660 states) holds every live checkpoint while those same conversations' KV (C·L·k, L≈20k) overflows the KV tier many times over. The "never binds" result is thus not a pool-sizing artifact — it is forced by #sequences ≪ #tokens. This is itself the law's most concrete practical consequence: an elastic cross-pool host allocator could reclaim the demonstrably-idle recurrent-state DRAM for the pressured attention-KV tier at large scale (a new axis vs device↔host exclusive tiering: it shares slack across components, enabled precisely by the O(#sequences) state footprint). We are careful to classify this correctly: it is still a capacity mechanism (it enlarges the effective KV tier beyond its 768 GB budget), so under this venue's rules it belongs to the baseline class and is not an exception to our impossibility (which excludes capacity increases); we report it as actionable provisioning guidance, not a claimed novel primitive. It would, however, help only at the pressured (intended) scale, and only if the budget ceiling is interpreted as total host rather than per-tier.

Where the improvement actually is. Two levers survive our analysis, both outside lossless recurrent-state caching: (1) attention-KV capacity — the sole cache lever, already captured by exclusive tiering and bounded by the frozen host budget; and (2) prefill compute — the true operating bottleneck (bursty long-context attention), addressable only by approximation (KV sparsity / partial attention), which is lossy and out of scope for a lossless cache study. A promising hybrid-specific hypothesis for future work: full-attention layers may tolerate more aggressive sparsification because the interleaved linear-attention layers already carry the long-range pathway — but this must be quality-gated, not output-matched.
